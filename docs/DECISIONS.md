# Решения

Формат: дата · шаг · решение — почему.

## 2026-10-24 · шаг 0

- **В работу берётся только пункт — узел без детей.** Задача с пунктами → `ApiError::ItemRequired`; несуществующий id → `ItemNotFound`. Узел верхнего уровня без детей — тоже пункт (SPEC: «пункт без родителя допустим»). Иначе время на задаче с пунктами неясно куда относить (Jira worklog — на задачу, комментарий — текст пункта).
- **`ApiError` расширен** сверх списка плана: `WrongSessionKind { expected, actual }` («Стоп» во время работы, «Прервать» во время отдыха/планирования — это не «нет сессии» и не «уже активна»), `Unauthorized` (Bearer-токен), `Transport(String)` (создаёт только клиент `HttpApi` при сетевой ошибке) и `Unknown` (`#[serde(other)]`, для новых кодов от нового сервиса). JSON: `{"code": "...", "details": ...}`. HTTP: 409 — конфликты состояния (`NoActiveSession`, `SessionAlreadyActive`, `WrongSessionKind`, `DayClosed`), 404 — `ItemNotFound`, 422 — `ItemRequired`, `Validation`, 401, 503 — плагин, 500 — внутренняя.
- **`ActiveSession` несёт `session_id`**, у `Work` — `ItemRef` (id, название, родитель), у `Planning` нет `ends_at`. JSON: тег `kind`.
- **«Готово», «Прервать», «Стоп» возвращают `SessionEndResult { ended, status }`** — клиенту сразу видны закрытая сессия (длительность, `end_reason`) и новое состояние (например, уже идущий отдых). Старты и операции с днём возвращают `StatusDto`.
- **Планирование закрывается стартом работы или отдыха** (`end_reason = switched`), а не ошибкой; работа и отдых не прерываются стартом другой сессии (`SessionAlreadyActive`).
- **`close_day` при активной сессии → `SessionAlreadyActive`.** `open_day` по закрытому сегодняшнему дню открывает его снова (тот же `DayId`, `closed_at = null`). Старт сессии в закрытый день → `DayClosed`.
- **`StatusDto.server_time`** — клиент считает таймер от времени сервиса, а не от своих часов. `idle_since` — начало текущего потерянного времени.
- **`TaskPatch`**: отсутствующее поле — не менять, `null` — очистить (`Option<Option<T>>` для `notes`, `planned_for`, `estimate_intervals`).
- **Настройки длин — в минутах (`*_min`), всё остальное — в секундах (`*_sec`)**; настройки плагинов — `BTreeMap<String, serde_json::Value>`, схему знает плагин; секреты не возвращаются. Поэтому `serde_json` в зависимостях `api-types` (собирается в wasm).
- **wasm: `uuid` с `js`, `chrono` с `wasmbind`** — только для `wasm32-unknown-unknown`, чтобы `Uuid::now_v7()` и `Utc::now()` работали в браузерном `MockApi`.
- **События SSE** — только тип `ServerEvent` (`{"type", "data"}`, `event:` = `ServerEvent::name()`); метода подписки в `FocusApi` нет, чтобы не тянуть `futures`/runtime в контракт. Клиент подписывается на `/api/events` сам.
- **Сценарии контракта** (`focus-api-contract-tests`) требуют свежий бэкенд; сценарий, оставляющий активный отдых (его нельзя пропустить), идёт в `run_all` последним. С управляемыми часами (`TestClock`, `run_all_with_clock`) сценарии проверяют точные длительности. Самопроверка — эталонный мок в `crates/api-contract-tests/tests/reference_mock.rs` (только для тестов, не для UI).
- **`reqwest` без default features**: `json`, `stream`, `rustls`, `http2` — без системного OpenSSL. `sqlx` без default features: `runtime-tokio`, `sqlite` (bundled), `migrate`, `macros`, `chrono`, `uuid`, `json`.
- **Проверка шага 0** (`fmt`, `clippy --workspace --all-targets -D warnings`, `test --workspace`, `check --workspace`, wasm-check `focus-api-types`) — зелёная на всём workspace, включая `apps/`. `dx build` в этом окружении не запускался (нет `dx`); его прогоняет сессия B.

## 2026-10-24 · UI (сессия B)

- **Визуальное направление — «тихий инструмент».** Графитовый почти-чёрный фон с тремя слоями возвышения (`--surface-1..3`), много воздуха, на экране один фокус. Главный образ — циферблат из минутных рисок: у работы их 50, у отдыха 10; оставшиеся минуты горят цветом сессии и гаснут по одной, текущая минута — белая риска, внутри тонкая дуга считает секунды. Цвет сессии семантический и одинаковый везде (кольцо, шкала дня, полоса нормы, точки легенды): работа — синий `#5B8CFF`, отдых — зелёный `#3DD68C`, планирование — янтарный `#F5B841`, потерянное время — серая штриховка, прервано — приглушённый красный акцент слева. Шрифты в комплекте: Inter — интерфейс, JetBrains Mono (табличные цифры) — таймеры и длительности. Движение сдержанное: дуга и риски меняются с шагом в секунду, свечение за циферблатом плавно меняет цвет при смене сессии, диалоги появляются с коротким подъёмом; `prefers-reduced-motion` всё отключает. Токены — в `apps/ui/assets/tokens.css`.
- **Шрифты — папкой-ассетом, `@font-face` собирается в коде** (`ui/src/fonts.rs`): после хэширования CSS-ассета относительные `url()` указывали бы в никуда.
- **«Готово» — двухшаговое**: нажатие открывает выбор «Отдых 10 минут / Спланировать следующую», и только выбор вызывает `done(next)` — так в контракте (`done` требует `next`). Esc закрывает выбор, работа продолжается.
- **Горячие клавиши «Фокуса»** — один глобальный `keydown` через `document::eval`: Space/Enter — главное действие (в простое — открыть выбор пункта / начать, в работе — «Готово», в планировании — «Начать работу»), Esc — закрыть диалог. В полях ввода и на кнопках не перехватываются, чтобы не ломать обычный ввод и активацию кнопки с клавиатуры.
- **Опрос вместо SSE (пока).** Клиент раз в секунду читает `get_status` и `get_day`; таймер считается от `ends_at - server_time`. С `HttpApi` опрос заменит подписка на `/api/events`.
- **`MockApi` — самостоятельная реализация** с ленивой обработкой лимитов (истечение работы → отдых, конец отдыха → потерянное время) и своими часами (`FOCUS_MOCK_SPEED`). Для демо и скриншотов: `FOCUS_MOCK_SCENARIO` (`idle|work|rest|planning|picker|interrupt|done-choice|tasks|day|empty`) и `FOCUS_WINDOW_SIZE`.
- **Пункты без родителя на экране «Задачи»** собраны в одну карточку «Без задачи» в конце списка.
- **Зависимости `apps/ui` сверх `dioxus` и `focus-api-types`:** `async-trait` (нужен для `impl FocusApi`) и `futures-timer` (задержка, одинаковая на desktop и в wasm). `apps/desktop`: `notify-rust`. Перенос в `[workspace.dependencies]` — за сессией A.
## 2026-10-24 · шаг 1

- **`DomainEvent` определён в `focus-core`** (`ItemCreated`, `ItemCompleted`, `SessionClosed`, `TaskImported` + `Unknown`), а `plugin-api` на шаге 5 его реэкспортирует. Публикует события ядро, и ядро не может зависеть от `plugin-api` (там `sqlx`/`axum` в трейте `Plugin`). События несут доменные сущности целиком (пункт + родитель), чтобы плагину не ходить в хранилище; JSON — `{"type", "data"}`.
- **`FocusService`: inherent async-методы с `Send`-future + тонкая реализация `FocusApi`** (`?Send`) поверх них. Сервер (Axum) вызывает inherent-методы, сценарии контракта — трейт. Ошибки ядра — `CoreError` (те же бизнес-варианты, что `ApiError`, + `Storage` → `ApiError::Internal`).
- **Порты — `#[async_trait]` (Send)**: `DayRepo`, `TaskRepo`, `SessionRepo`, `SettingsRepo`, `EventSink` (outbox), `TaskSources` (реестр `TaskSource`; `NoTaskSources` → `PluginUnavailable`), `Clock`. Собираются в `Ports`. Реализации в памяти — `focus_core::memory` (`std::sync::Mutex`, без tokio).
- **Команды сериализованы** асинхронным мьютексом `futures-util` (без runtime); транзакций в портах нет — при одном владельце SQLite и одной команде за раз этого достаточно. Импорт ходит в источник вне блокировки.
- **«Догон» времени перед каждой командой**: истёкшая работа закрывается в свой `ends_at` с `limit` и сразу стартует отдых (в тот же день, даже если он закрыт/наступила новая дата), истёкший отдых — с `limit`. Поэтому статус верен и без фонового таймера. `tick(now)` делает то же и возвращает `SessionEnded` по всем сессиям, закрытым таймером с прошлого вызова (включая закрытые «догоном»), затем `StatusChanged`. Сессии, закрытые командой («Готово»/«Прервать»/«Стоп»), в `tick` не попадают — клиент видит их в ответе. `next_deadline()` подсказывает таймеру, когда проснуться.
- **Пояс — в `Clock::local_date(at)`**: `SystemClock` — `chrono::Local`, `ManualClock` — фиксированное смещение (тесты, мок).
- **Текущий день в статусе** — день активной сессии (через полночь сессия остаётся во вчерашнем дне, и `worked_today_sec` считается по нему), иначе — день сегодняшней локальной даты (может не быть). Новая сессия по команде всегда идёт в сегодняшний день (автооткрытие).
- **Потерянное время** — промежутки без сессий в `[opened_at, конец)`, где конец — `closed_at` закрытого дня, «сейчас» для открытого сегодняшнего, а у прошлого незакрытого дня хвост после последней сессии не считается. `idle_since` — конец последней сессии (или открытие дня).
- **Лимит сессии и норма дня фиксируются при старте/открытии**: `PUT /api/settings` действует на новые сессии и дни. Пределы: `work_min` 1..=240, `rest_min` 1..=120, `daily_target_min` 1..=1440, иначе `Validation`.
- **Задачи**: глубина — два уровня (у пункта детей нет → `Validation`); нельзя добавить пункт к узлу в активной работе. Название обрезается по краям, пустое или > 500 символов → `Validation`. `sort_order` нового узла — max среди соседей + 1; дерево сортируется по `(sort_order, created_at, id)`. Старт работы переводит `planned` → `in_progress`; пункт `done`/`cancelled` в работу не берётся (`Validation`). `done_at` ставится при переходе в `done` и сбрасывается при уходе из него; `ItemCompleted` — при переходе в `done` («Готово» или PATCH).
- **`close_day`, когда сегодня день не открывался** → `Validation`. `get_day` для даты без дня — пустой `DayDto` с нормой из настроек.
- **Импорт**: повторный по той же канонической ссылке (`ImportedTask.url` = `external_url`) не дублирует задачу и не меняет её название, а добавляет пункты с новыми названиями (сопоставление по тексту); статусы пунктов — из источника. `ItemCreated` при импорте не публикуется (пункты уже есть в источнике), публикуется `TaskImported`. `plugin_status` в ядре — пустой список (наполнит сервер на шаге 5).

## 2026-10-24 · шаг 2

- **Типы колонок SQLite**: UUID — `TEXT` (нижний регистр, с дефисами); моменты — `TEXT` RFC3339 UTC с наносекундами фиксированной длины (`2026-10-24T09:00:00.000000000Z`) — читается глазами, сравнение строк в SQL совпадает с порядком времени, точность `DateTime<Utc>` не теряется; даты — `TEXT YYYY-MM-DD`; перечисления — их serde-имена (`in_progress`, `task_done`). Таблицы `STRICT`, `CHECK` на перечисления, на «у работы есть пункт» и «`ended_at` ⇔ `end_reason`».
- **Норма дня — `work_days.target_sec`** (в SPEC `target_minutes`): в домене и API — секунды, конвертации не нужны.
- **`tasks.external_url`** — колонка ядра (ссылка на источник импорта), индекс для повторного импорта. Внешние ключи: `tasks.parent_id → tasks`, `sessions.day_id → work_days`, `sessions.task_id → tasks`.
- **Одна активная сессия** — гарантия БД: уникальный частичный индекс `WHERE ended_at IS NULL`. Ядро всегда сначала закрывает сессию, потом открывает новую, поэтому индекс не мешает.
- **`settings(key, value)`**: значения — JSON по ключам `work_min`, `rest_min`, `daily_target_min`, `plugins`; отсутствующий ключ — значение по умолчанию, неизвестные игнорируются. Сохранение — одной транзакцией.
- **Outbox — запись на пару (событие, плагин)**: `publish` раскладывает событие на подписчиков (`Outbox::set_subscribers`, id включённых плагинов задаёт сервер); без подписчиков события не пишутся. `id INTEGER AUTOINCREMENT` задаёт порядок. В порт ядра добавлен трейт `Outbox: EventSink` (`fetch_due`, `mark_done`, `mark_failed`, `stats`) и модуль `focus_core::outbox` (`OutboxEntry`, `OutboxStats`, `backoff`, `select_due`); `MemoryOutbox` реализует его так же. Добавлена колонка `last_error_at` (нужна `/api/plugins/status`).
- **Повторы**: задержка 10 с · 2^(n−1), не больше часа. Записи плагина отдаются строго по порядку: после записи, ждущей повтора, следующие записи того же плагина не выдаются (иначе «пункт готов» мог бы обогнать «пункт создан» в Jira). Другие плагины не блокируются.
- **Подключение**: `Storage::open(path)` создаёт каталог и файл, WAL, `synchronous=NORMAL`, `busy_timeout` 5 с, `foreign_keys=ON`, пул на 4 соединения; `Storage::open_in_memory()` — одно бессрочное соединение. Миграции `sqlx::migrate!("./migrations")` применяются при открытии; запросы — runtime (`sqlx::query`), без `DATABASE_URL` и offline-кэша. Ошибки — `StorageError` (thiserror) → `CoreError::Storage`.

## 2026-10-24 · шаг 3

- **Токен — файл `token` в data dir с правами `0600`**, а не `keyring`: в v1 сервис локальный, файл читается `focus-flow token` и клиентом без системных диалогов доступа к связке ключей, работает в headless/CI. 32 случайных байта (`getrandom`) в hex. Файл создаётся атомарно (`create_new`, сразу `0600`); если права шире — исправляются при старте. Переезд в `keyring` — при переезде на VDS/мобильный клиент.
- **Data dir** — `directories::ProjectDirs("dev", "FocusFlow", "focus-flow")` (Linux `~/.local/share/focus-flow`, macOS `~/Library/Application Support/dev.FocusFlow.focus-flow`), БД — `focus.db`. Порядок конфигурации: умолчания → `FOCUS_ADDR`, `FOCUS_DATA_DIR`, `FOCUS_ALLOWED_HOSTS`, `FOCUS_ALLOWED_ORIGINS` (списки через запятую) → флаги `--addr`, `--data-dir` у `serve` и `token`. Адрес не loopback — только предупреждение в лог.
- **`App`** = `Storage` + `Arc<FocusService>` + `broadcast::Sender<ServerEvent>` (ёмкость 256; отставший подписчик SSE теряет старые события) + токен + конфиг. `App::from_parts` — для тестов (БД в памяти, `ManualClock`).
- **Таймер** спит до `next_deadline()`, но не дольше 1 с, и на каждом пробуждении вызывает `tick(now)` — он дешёвый и заодно отдаёт `SessionEnded` сессий, закрытых «догоном» внутри команд. Опрос раз в секунду страхует от сна системы, сдвига часов и команд, поменявших дедлайн (будить таймер из обработчиков не нужно). Ошибки шага — в лог, цикл продолжается.
- **Уведомления** — только для сессий, закрытых по лимиту: работа → «Время работы вышло — отдохни N минут» (N — текущий `rest_min`), отдых → «Отдых окончен — выбери следующую задачу». Трейт `Notifier`; `notify-rust` за фичей `notify` (по умолчанию включена в `focus-flow`; в workspace-зависимости `focus-server` — `default-features = false`, фичи выбирает потребитель). Показ — в `spawn_blocking`, ошибки только логируются. Звук — системный звук уведомления.
- **Остановка** — Ctrl+C и SIGTERM (launchd/systemd): graceful shutdown Axum, отмена таймера (`CancellationToken`), закрытие пула SQLite.

## 2026-10-24 · шаг 4

- **Пути — ровно таблица SPEC** под `/api` + `GET /api/health` (без токена; `{"status":"ok","version"}`). Тела: `POST /api/sessions/work` — `{item_id}`, `.../active/done` — `{next}` (`api_types::requests`), `POST /api/import` — `ImportRequest`, `POST /api/tasks` → `201 Created`, остальные успехи — `200`. Тела ответов — DTO `api-types` без обёрток.
- **Ошибки** — JSON `ApiError` (`{"code","details"}`) со статусом `ApiError::http_status()`. Неразборчивое тело или параметр пути (не UUID, не `YYYY-MM-DD`) — тоже `422 validation`, а не текстовый ответ Axum, чтобы клиент всегда получал `ApiError`.
- **`ApiError::Forbidden(String)` → 403** добавлен в контракт: отказ проверки `Host`/`Origin`. Старые клиенты читают его как `Unknown`.
- **Порядок проверок** (middleware на всех `/api/*`): `Host` → `Origin` → токен. `Host` — `127.0.0.1`, `localhost`, `[::1]` с любым портом + `FOCUS_ALLOWED_HOSTS` (для VDS). Сравнение токена — за постоянное время. На 401 — `WWW-Authenticate: Bearer`.
- **`Origin`**: нет заголовка — разрешено (нативный HTTP-клиент desktop, curl, MCP-клиенты). Разрешены всегда: схемы custom protocol webview `dioxus://`, `tauri://`, `wry://`; `http(s)://dioxus.localhost` и `http(s)://tauri.localhost` (так webview подменяет custom protocol на Windows/Android); `null` (sandbox/`file://`); loopback-страницы `http(s)://127.0.0.1:*`, `localhost:*`, `[::1]:*` (dev-сервер web-клиента — сам по себе уже loopback). Дополнительно — `FOCUS_ALLOWED_ORIGINS`: точное значение или `scheme://` для всей схемы. Остальное — `403`. Ни одна чужая страница в браузере не может ни читать, ни слать команды (даже «простые» POST без preflight): отказ — до обработчика.
- **CORS** — только для разрешённого `Origin`: `Access-Control-Allow-Origin` = этот `Origin` (не `*`), `Vary: Origin`; preflight `OPTIONS` → `204` без токена (методы `GET, POST, PUT, PATCH, OPTIONS`, заголовки `authorization, content-type`). Без cookies — `Allow-Credentials` не нужен. Отдельный `tower-http` не подключали: логика в том же middleware, что и проверка `Origin`.
- **Токен в `?token=`** принимается только для `GET /api/events` (браузерный `EventSource` не ставит заголовки); на остальных путях — только заголовок, чтобы токен не попадал в логи/историю без нужды.
- **SSE `/api/events`**: `event: <ServerEvent::name()>`, `data:` — JSON события `{"type","data"}`; первым приходит текущий `status_changed` (клиенту не нужен отдельный `GET /api/status` после переподключения); при переполнении шины — свежий `status_changed` вместо пропущенных; keep-alive — комментарий `: ping` раз в 15 с. Поток закрывается по `CancellationToken` остановки сервиса — иначе graceful shutdown ждал бы открытые SSE вечно.
- **Кто публикует события**: команды REST — `status_changed` (старты, день, настройки), `session_ended` + `status_changed` («Готово», «Прервать», «Стоп»), `task_changed` (создание/правка/импорт, старт работы и «Готово» — у пункта меняется статус). Таймер — `session_ended` по лимиту + `status_changed`. Команды MCP (шаг 6) будут публиковать так же.
- **`RestState`** — `Arc<FocusService>`, `broadcast::Sender<ServerEvent>`, `Arc<Access>`, `CancellationToken`; `api-rest` не зависит от `focus-server` и `focus-storage` (хранилище — только в тестах). `focus-server::router(&App)` собирает итоговый `Router` через `merge` — туда же подключатся `/mcp` и маршруты плагинов.
- **Контракт поверх REST**: тестовый `RouterApi` (реализация `FocusApi` на `tower::ServiceExt::oneshot` через весь стек: проверки, JSON, коды) гоняет `run_all_with_clock` на SQLite в памяти с `ManualClock` и заодно проверяет, что HTTP-статус каждой ошибки совпадает с `http_status()` её кода.

## 2026-10-24 · UI: подключение к сервису (сессия B)

- **`HttpApi`** (`apps/ui/src/api/http.rs`) — `FocusApi` поверх REST на `reqwest` 0.13 с явной версией в `apps/ui`, без TLS (`default-features = false`, `json` + `stream`): сервис локальный, `http://127.0.0.1`. Workspace-версия включает `rustls` (aws-lc), а фичи у зависимости убрать нельзя, поэтому её не используем. На desktop reqwest ходит через hyper, в wasm — через `fetch`, так что код один. Токен — `Authorization: Bearer`. Ответ не 2xx → `ApiError` из JSON-тела; если тело не JSON, ошибка строится по статусу. Сеть, таймаут (10 с) и неразборчивый ответ → `Transport`. Токен берётся из функции и перечитывается после `401`, поэтому desktop подхватывает пересозданный файл `token` без перезапуска.
- **Живые обновления — SSE**, свой минимальный разбор `text/event-stream` поверх `bytes_stream()`. Читаются только строки `data:`, тип события берётся из JSON, `: ping` служит признаком живого соединения. В wasm работает тот же код: reqwest в браузере стримит тело `fetch`. Токен идёт заголовком, `?token=`/`EventSource` не нужны. `web_sys::EventSource` не взяли: ради него пришлось бы держать второй код и класть токен в URL.
- **Источник данных в UI.** У сервиса это SSE плюс страховочный опрос раз в 15 с (сон системы, потерянные события). У мока событий нет, остаётся опрос раз в секунду. `status_changed` применяется сразу и перечитывает день. `task_changed` перечитывает дерево задач. `session_ended` отдельно не обрабатывается: за ним сервис всегда шлёт `status_changed`. Если ответ опроса старше уже применённого события (по `server_time`), он отбрасывается.
- **Ход времени локально.** Хранятся последние снимки статуса и дня с моментом получения по местным часам. Раз в секунду, по границе секунды часов сервиса, показываемые значения сдвигаются на прошедшее время: `server_time`, `worked_today_sec` (если идёт работа или планирование), длительность активной сессии и итоги её вида. Таймер считается от `ends_at − server_time`, поэтому расхождение часов клиента и сервиса не важно. Мок так не досчитывается: он и так опрашивается каждую секунду и может стоять на месте (`FOCUS_MOCK_SPEED=0`).
- **Переподключение SSE**: 0,5 → 1 → 2 → 4 → 5 с (потолок). Соединение считается мёртвым, если нет ни данных, ни keep-alive 40 с. После переподключения дерево задач перечитывается, а статус приходит первым событием потока. Пока связи нет, сверху экрана висит тонкая плашка «Нет связи с сервисом · Переподключаюсь… Запусти: `focus-flow serve`»; на `401` вместо неё «Сервис не принял токен… `focus-flow token`». Последние данные остаются видны. Тост с тем же «Нет связи…» на это время скрыт.
- **Команды UI запускаются через `spawn_forever`, а не через `spawn`.** `spawn` привязывает задачу к компоненту, который её вызвал. Часто это диалог, который та же команда и закрывает (выбор пункта, «Готово», «Прервать»), и запрос к сервису отменялся на лету: с моком этого не было видно, потому что его future готовы сразу.
- **Desktop по умолчанию работает с сервисом**: адрес — `FOCUS_ADDR` или `127.0.0.1:7878`, схему можно не писать. Токен — `FOCUS_TOKEN`, иначе файл `token` в `FOCUS_DATA_DIR` или в каталоге данных сервиса (`directories::ProjectDirs("dev", "FocusFlow", "focus-flow")`, та же версия 6, что у сервиса). Мок включается через `FOCUS_MOCK=1` или любой заданный `FOCUS_MOCK_SCENARIO`; остальные `FOCUS_MOCK_*` работают как раньше.
- **Уведомления не дублируются.** Сервис сам показывает системное уведомление при закрытии сессии по лимиту (работа → отдых, конец отдыха). Клиент с `HttpApi` поэтому `Platform::notify` не вызывает. Свои уведомления о переходах UI показывает только с моком.
- **Контракт по HTTP**: `apps/ui/tests/http_contract.rs` прогоняет `run_all` на `HttpApi` против запущенного сервиса (`#[ignore]`, нужны `FOCUS_TEST_ADDR` и `FOCUS_TEST_TOKEN`). Заодно тест проверяет, что первым событием SSE приходит `status_changed`, что события сценариев доходят по SSE и что неверный токен даёт `Unauthorized`. Без сервиса выполняется тест на `Transport` для недоступного адреса. `tokio` (`rt`, `macros`, `time`) — только в dev-зависимостях `ui`.
- **Новые зависимости `apps/*`** (перенос в `[workspace.dependencies]` — за сессией A): `ui` — `reqwest` 0.13.5 (без TLS), `serde`, `serde_json`, `futures-util`; dev — `tokio`. `desktop` — `directories` 6.
