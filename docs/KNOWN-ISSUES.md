# Известные ограничения и непроверенное

Состояние на 2026-10-24 (MVP, шаг 8). Здесь честно перечислено, что не проверялось в реальных условиях или сделано с ограничениями.

## Проверено только в контейнере (Linux, Xvfb)

- **Окно проверялось только на Linux под Xvfb** (WebKitGTK, программный рендер), скриншотами и `xdotool`. На настоящем macOS и Windows приложение не запускалось: не смотрели шрифты, масштаб Retina, меню, поведение при закрытии окна и сне системы.
- **Системные уведомления** (`notify-rust`) на реальном рабочем столе не видели. В контейнере нет D-Bus сессии уведомлений, а на macOS уведомлениям может понадобиться разрешение для бинарника, не упакованного в `.app`. Звук при окончании работы — только звук самого уведомления (`sound_name`). Если уведомление не показано, звука не будет.
- **Wake lock не реализован** (`Platform::keep_awake` — заглушка): во время работы система может уснуть. После пробуждения клиент догоняет сервис по SSE и страховочному опросу, но таймер на это время «засыпает» вместе с системой.
- **launchd-шаблон** (`scripts/macos/dev.focusflow.serve.plist`) проверен только как валидный plist. `launchctl load` на macOS не запускали.
- **`focus-flow ui`**: в контейнере проверены запуск с новым каталогом данных, подключение к уже запущенному сервису и штатная остановка сервиса по «Выходу» в трее и по SIGTERM (в том числе при спрятанном окне). Закрытие через ⌘Q на macOS и через диспетчер задач Windows не проверялось.
- **Ассеты в сборке cargo** берутся из исходников репозитория (`apps/ui/assets`): бинарник из `cargo install` работает, только пока жив клон репозитория. Переносимый пакет собирается `dx bundle` — его собирали (`dx build`), но установку пакета на чистую машину не проверяли.

## Трей / строка меню

- **Трей проверен только на Linux под Xvfb** — с `xfce4-panel` (область значков StatusNotifier). Проверены: смена значка по фазам (работа → отдых по лимиту → простой, планирование, нет связи и восстановление), подпись со временем (свойство `XAyatanaLabel` элемента; сама панель XFCE её не рисует), меню по фазам и все его команды (клик через dbusmenu), «Прервать…» и «Начать работу…» (окно с предупреждением / выбором пункта, сессия не прерывается), «Открыть» с другого экрана, закрытие окна (`WM_DELETE_WINDOW`) — окно прячется, трей продолжает тикать, команды из трея работают, «Выход» останавливает сервис. Кадры панели по фазам — [`screenshots/tray-linux-xfce.png`](screenshots/tray-linux-xfce.png), набор значков — [`screenshots/tray-icons.png`](screenshots/tray-icons.png).
- **На macOS и Windows трей не запускался.** Код для них проверен только кросс-компиляцией (`cargo clippy --target aarch64-apple-darwin` / `x86_64-pc-windows-msvc`). Не видели: template-значок в светлой и тёмной теме, время рядом со значком и моноширинные цифры, левый клик по значку, ⌘W / ⌘Q / клик по Dock при спрятанном окне, подсказку и цветной значок в трее Windows. Скриншотов строки меню macOS нет.
- **Подпись на Linux видна не во всех окружениях** (KDE и обычный systray XFCE её не показывают), подсказок AppIndicator не поддерживает — там время видно только в окне.
- **«Отдых 10 минут»** в подменю «Готово» — текст как на кнопке экрана; при другом `rest_min` он не меняется (длительность отдыха клиенту не приходит).

## Интеграции

- **MCP не проверен с живым клиентом Claude.** Инструменты покрыты тестами: сырой JSON-RPC (Streamable HTTP) поверх роутера, без сети. `claude mcp add …` и Claude Desktop с `mcp-remote` не запускались: инструкции в README написаны по документации.
- **Jira проверялась только на заглушках**: `wiremock` в тестах и маленький фальшивый сервер при ручной проверке UI (импорт, проверка подключения, worklog). С настоящей Jira (ни Data Center, ни Cloud) плагин не работал ни разу. Не проверены реальные коды и тексты ошибок, права, капча после неверных токенов, rate limit, прокси и самоподписанные сертификаты.
- **Smart Checklist** не проверен ни на Data Center, ни на Cloud. Формат поля (текст, строка на пункт, маркеры `- + ~ x`) и запись `PUT /rest/api/2/issue/{key}` всем полем взяты из документации Railsware. На Cloud чек-лист может храниться иначе (свойство задачи или своё API приложения) — тогда импорт найдёт задачу без пунктов, а запись строк не сработает.
- **Поиск поля чек-листа по имени** («Smart Checklist» или содержащее «Checklist») может выбрать не то поле, если таких полей несколько. Тогда поле надо указать вручную в «Настройках».
- **Сопоставление пунктов со строками чек-листа — по тексту.** Если строку переименовали в Jira, а пункт — у нас, связь теряется: пункт будет отмечен готовым только у нас, а в лог попадёт предупреждение.
- **Токен Jira лежит в файле** `secrets/jira/token` (права `0600`), а не в системном хранилище ключей (`keyring`), хотя SPEC его допускает. Токен доступа к сервису тоже лежит в файле.

## Клиенты

- **web и mobile — заготовки.** `apps/web` собирается под wasm и работает только на `MockApi`. `apps/mobile` исключён из workspace.
- **Настройки длительностей и нормы** (`work_min`, `rest_min`, `daily_target_min`) есть в API (`PUT /api/settings`), но экрана для них в UI нет.
- **Нет правки задач в UI**: переименования, заметок, удаления, переноса пунктов и `planned_for` (в API и MCP всё это есть). Отменить задачу можно только через API или Claude (`status: cancelled`).
- **День нельзя закрыть или открыть из UI** (в API и MCP можно). Календаря по прошлым дням тоже нет: экран «День» показывает только сегодня.
- **Нет правки сессий задним числом** — по SPEC это вне v1. Ошибочно начатую работу можно только прервать: она попадёт в отчёт как прерванная.
- **Ввод кириллицы через `xdotool`** в автотестах не работает (ограничение `xdotool`, не приложения). Поэтому ручной ввод на русском под Xvfb не проверен; задачи на русском создавались через REST.
- **Доступность** проверялась только по разметке (`aria-*`, роли). Скринридером интерфейс не проверяли.

## Сервис

- **Один процесс — одна БД.** Если запустить два `focus-flow serve` с одним каталогом данных на разных портах, каждый будет писать в SQLite сам по себе. Защиты (lock-файла) нет.
- **Часовой пояс** берётся из системы при каждом расчёте границ дня. Если сменить пояс посреди дня, отчёт за этот день может сдвинуться.
- **Полночь**: сессия через полночь относится ко дню старта (по SPEC). Если день не закрыли вручную, он остаётся открытым, а следующий день открывается заново при первом старте. Корректность отчёта за ночь проверена только тестами ядра.
- **Удалённый режим (VDS)** не проверялся: `FOCUS_ALLOWED_HOSTS`/`FOCUS_ALLOWED_ORIGINS` и bind не на loopback есть, а TLS у сервиса нет — нужен обратный прокси.

## Найдено при независимой проверке (2026-10-24)

- **Пункт без задачи → задача.** Быстрый ввод на «Задачах» создаёт узел верхнего уровня, и он показывается в группе «Без задачи». Чтобы разбить его на пункты, у такой строки есть кнопка «+ Пункт». После первого добавленного пункта строка становится задачей, поле ввода пропадает, и следующий пункт добавляется кнопкой «+ Пункт» уже у задачи. Набранное до этого в старом поле теряется.
- **macOS:** уведомления сервиса идут через устаревший `NSUserNotificationCenter` (`notify-rust` 4.x) от имени чужого bundle id (по умолчанию Finder), потому что бинарник не упакован в `.app`. Уведомление может не показаться или прийти без звука. Тогда окончание сессии видно только в окне.
- **Нет экрана длительностей**: чтобы попробовать короткие интервалы, `PUT /api/settings` нужно слать со всеми полями (`work_min`, `rest_min`, `daily_target_min`, `plugins`). Частичное тело → `validation`.
